## 1. Введение

Идентификация личности по голосу относится к биометрическим технологиям: человек распознаётся по устойчивым характеристикам речевого сигнала. В отличие от распознавания речи (ASR), где важно *что* сказано, здесь важно *кто* говорит.

**Цель работы** — спроектировать и реализовать учебный прототип системы идентификации по голосу на основе признаков MFCC и голосового слепка.

**Задачи:** анализ методов; проектирование архитектуры; реализация на Python; сбор данных и эксперименты; оформление результатов.

Различают:
- **Speaker identification** — кто из базы говорит (задача 1:N, реализована в прототипе);
- **Speaker verification** — подтверждение заявленной личности (1:1);
- **ASR** — распознавание текста.

## 2. Анализ объекта

### 2.1. Речь как звуковой сигнал (Лекция 3)

Звук — изменение звукового давления во времени. Для обработки на ПК аналоговый сигнал микрофона проходит АЦП: дискретизация и квантование. По теореме Котельникова частота дискретизации должна быть не ниже удвоенной верхней частоты сигнала. Для речи достаточно порядка 6–8 кГц верхней полосы, поэтому в системе принята частота **16 кГц** при 16-битовом представлении — компромисс качества и объёма данных, согласованный с материалом лекции о модуле записи/воспроизведения.

### 2.2. Формат WAV (Лекция 13)

Рабочий формат — Wave (RIFF): в заголовке хранятся частота дискретизации, разрядность и число каналов. В прототипе вход приводится к mono 16 kHz; спектральный анализ выполняется через БПФ (аналог функции Spectrum Analysis в звуковых редакторах, упомянутых в лекции).

### 2.3. Тембр голоса (Лекция 4)

Любой звук характеризуется частотой основного тона и обертонами, задающими **тембр**. У человека тембр определяется формой голосового тракта (резонансы — форманты). Система не хранит «сырую волну», а сжимает информацию о спектральной окраске в компактный вектор — **голосовой слепок**, что концептуально соответствует идее тембровой окраски из лекции о синтезе звука.

### 2.4. Постановка задачи

Два режима:
1. **Enrollment** — по нескольким фразам строится слепок пользователя.
2. **Identification** — тестовая фраза сравнивается со всеми слепками; при сходстве ниже порога — отказ.

Метрики качества (см. ТЗ): Accuracy, FAR, FRR.

## 3. Обзор методов

| Подход | Идея | Сложность для КП |
|--------|------|------------------|
| Mean MFCC (слепок) | усреднить признаки по кадрам, сравнить cosine | низкая, объяснима |
| GMM | смесь Гауссиан на MFCC | средняя |
| i-vector / x-vector | статистические / нейросетевые эмбеддинги | высокая, «чёрный ящик» |

**Выбор:** MFCC + mean-vector + cosine similarity. Этого достаточно для демонстрации принципа и защиты с опорой на лекции; GMM оставлен как развитие.

### 3.1. MFCC кратко

1. Разбиение на кадры (25 мс) с перекрытием (10 мс).  
2. Окно Хэмминга, БПФ, спектр мощности.  
3. Банк треугольных фильтров на **mel-шкале** (близка к восприятию).  
4. Логарифм энергий → ДКП → коэффициенты MFCC.  

Слепок — среднее по кадрам после VAD, L2-нормировка.

## 4. Проектирование системы

Архитектура соответствует этапам III–IV лекции 17 (сценарий, структуры, выбор ПО).

```
WAV → предобработка → MFCC → слепок
                              ↓
                         база .npy
                              ↓
              тест → cosine → порог → имя / отказ
```

**ПО:** Python 3, библиотеки `numpy`, `scipy`, `matplotlib`; GUI — `tkinter`.  
Признаки и сравнение реализованы самостоятельно (без librosa/sklearn), чтобы алгоритм был прозрачен на защите.

Структура данных:
- `data/raw/<speaker_id>/*.wav`
- `data/profiles/<speaker_id>.npy`

## 5. Реализация

Модули:
- `src/preprocess.py` — нормализация, energy VAD, pre-emphasis;
- `src/features.py` — Mel-фильтрбанк, MFCC, cosine;
- `src/enroll.py` / `src/identify.py` — регистрация и идентификация;
- `src/metrics.py` — оценка;
- `app/gui.py` — интерфейс.

Параметры зафиксированы в `src/config.py` (fs=16000, 26 mel, 13 MFCC без C0, порог 0.92).

## 6. Экспериментальная часть

### 6.1. Датасет

На этапе разработки использован синтетический демо-набор с различными формантными конфигурациями (имитация разных тембров). Для защиты бригада заменяет файлы реальными записями по протоколу `docs/RECORDING_PROTOCOL.md`.

Состав демо: 3 спикера × (6 enroll + 4 test) + 4 impostor.

### 6.2. Метрики

После `python -m src.metrics --sweep` — таблица `docs/metrics_table.csv`.

Результаты на демо-наборе при пороге **0.92**: Accuracy = 1.00, FAR = 0.00, FRR = 0.00  
(12 target-тестов + 4 impostor). На реальных голосах цифры будут скромнее — пересчитать и вставить актуальную таблицу.

Интерпретация:
- рост порога ↓ FAR, ↑ FRR;
- рабочий порог — компромисс (часто близок к EER).

### 6.3. Ограничения
- чувствительность к микрофону и шуму;
- малая база;
- нет защиты от спуфинга (воспроизведение записи).

## 7. Заключение

Реализован прототип идентификации личности по голосу на основе MFCC и голосового слепка. Подход согласован с материалом смежного курса по мультимедиа (оцифровка, тембр, спектр, этапы проектирования). Система пригодна для учебной демонстрации и дальнейшего развития (GMM, нейросетевые эмбеддинги).
