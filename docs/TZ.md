# Техническое задание

## Тема
Проектирование системы идентификации личности по голосу  
(КП, группы МЗО-206 / 207СВ-25, тема №5)

## Цель
Разработать программный прототип системы, которая по речевому сигналу определяет, принадлежит ли голос одному из зарегистрированных пользователей, либо отклоняет неизвестный голос.

## Задачи
1. Провести анализ методов идентификации по голосу (признаки, модели сравнения).
2. Спроектировать архитектуру системы (запись → признаки → слепок → сравнение).
3. Реализовать прототип на Python с минимальным набором библиотек.
4. Собрать учебную базу голосов бригады и провести эксперименты.
5. Оформить пояснительную записку и презентацию к защите.

## Функциональные требования
| ID | Требование |
|----|------------|
| FR-1 | Регистрация (enrollment): из нескольких WAV формируется голосовой слепок пользователя |
| FR-2 | Идентификация (1:N): входной WAV сравнивается со всеми слепками в базе |
| FR-3 | При максимальном сходстве ниже порога система отвечает «не распознан» |
| FR-4 | Поддержка файлов WAV 16 кГц, mono, 16 bit (и приведение к этому формату) |
| FR-5 | CLI для enroll / identify / evaluate |
| FR-6 | Простой GUI (выбор файла, результат идентификации) |
| FR-7 | Расчёт метрик Accuracy, FAR, FRR на тестовом наборе |

## Нефункциональные требования
- Объяснимость алгоритма на защите (без «чёрного ящика» нейросети).
- Зависимости: `numpy`, `scipy`, `matplotlib`; GUI — `tkinter` (stdlib).
- Время обработки одной фразы ~3–5 с: не более нескольких секунд на обычном ПК.
- Код и данные — локально, без сетевых сервисов.

## Режим работы
- **Text-independent** — фраза при регистрации и проверке может отличаться.
- Идентификация (кто из базы), не верификация «да/нет по заявленному имени» как единственный режим (имя выбирается автоматически по max score).

## Критерии успеха (метрики)

| Метрика | Определение | Целевое значение (учебный прототип) |
|---------|-------------|-------------------------------------|
| **Accuracy** | Доля правильных решений на тестах известных спикеров | ≥ 80 % |
| **FAR** (False Acceptance Rate) | Доля случаев, когда чужой/импостор принят как свой | ≤ 20 % |
| **FRR** (False Rejection Rate) | Доля случаев, когда свой отклонён | ≤ 20 % |
| **EER** (ориентир) | Порог, при котором FAR ≈ FRR | фиксируется в отчёте |

Порог cosine similarity подбирается на валидации (рабочее значение демо-набора: **0.92**, см. `src/config.py` и `docs/metrics_table.csv`).

## Ограничения
- Нет anti-spoofing (защита от записи с динамика).
- Нет pretrained embeddings / тяжёлых DNN.
- База — голоса бригады (3 человека) + импосторы для FAR.

2. Исходный код прототипа + README.
3. Презентация (~10–12 слайдов).
4. Учебный датасет (WAV) и профили слепков.
